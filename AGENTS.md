# Passion Project

Instructions for AI coding assistants (Claude, Codex, Copilot, Cursor, ...). `CLAUDE.md` points here; edit this file, not that one.

Private Fortnite server project. **Syndicate is the base** (Chapter 1 Season X, Fortnite 10.40). The former Project Tilted code is imported under `SyndicateClassic/` only as a source of parts to port into the main code where it is weaker; it is not the product.

The project used to be two projects (Titanium and Project Tilted); every name in the repo is now Syndicate. Players must never see the old names: the menu is `SyndicateMenu.dll`, Syndicate Studio's in-game helper is `SyndicateStudio.dll` (was `TiltedStudio.dll`), and the prebuilt client modules are installed in `Runtime\dlls` as `SyndicateClient.dll` / `SyndicatePadAssist.dll` (older installs still have them as `TiltedClient.dll` / `TiltedPadAssist.dll`; `dev/update-from-git.ps1` copies them under the new names and removes the old files). A few old names stay where players don't see them, because prebuilt binaries or saved data depend on them: `titanium-modes.cjs` / `titanium-profiles.cjs` (required by the prebuilt `lawinserver.exe`), the prebuilt `TiltedInject.exe`, the shared `%LOCALAPPDATA%\ProjectTilted` folder (read by the prebuilt client modules), the `project_tilted` MongoDB database, saved profile keys (`tilted_*`, `titanium_*`), `TILTED_*` environment variables, Fortnite cosmetic/quest IDs, and Fortnite places (Tilted Towers). Don't rename these. `Services/LegacyData.cs` (launcher) and `dev/common.ps1` / `dev/update-from-git.ps1` move data saved under the old folder names to the Syndicate names once.

Bot AI (`PlayerBots.h`, `Bot*.h`, `CombatSkills.h`), looting, vehicles, traps, storm, match flow. Its Start is the launcher's Play for the selected Chapter 1 season; while the Studio window is open it keeps `%LOCALAPPDATA%\ProjectTilted\studio-session.json` fresh and `GameLauncher` starts Erbium with `TILTED_DEV_LIVE=1`, the Studio's playlist and, for a Studio match, `TILTED_STUDIO=1` with no bots (endless warm-up). | `Launcher/BackendSource/` | JS source extracted from the prebuilt `lawinserver.exe` (LawinServer). Reference only; the backend that runs is the exe. | not built |
| `SyndicateMenu/` | Source of the in-game Syndicate menu (`SyndicateMenu.dll`, Insert opens, End unloads), by Trent. ## Dev workflow

- Each dev has a `Documents\Syndicate` folder from the dev kit (launcher exe + `Runtime\` with the DLLs and `lawinserver.exe`, which are not in Git) and a GitHub Desktop clone of this repo.
- `UPDATE FROM GIT.cmd` copies changed `Runtime` files into `Documents\Syndicate\Runtime`, copies `SyndicateClassic/backend` to `Documents\Syndicate\Syndicate-backend` (the launcher starts this backend via `Services/SyndicateBackend.cs`, with Node and MongoDB from `Documents\Syndicate\Dependencies`; the first time, `node_modules` and the runtimes are copied from an older Project Tilted install and topped up with `npm install`), rebuilds the two DLLs when `ServerAndConsole/` changed, builds a fresh `Erbium.dll` from `SyndicateClassic/game-server/Erbium` (cached in `%LOCALAPPDATA%\PassionProject\dev\erbium-build`, rebuilt when that source or its `SDK` changes; it replaces any Erbium copied from an older install), builds `SyndicateStudio.dll` from `SyndicateClassic/game-server/SyndicateStudio` the same way (`studio-build`; optional, a failed build only warns), rewrites `Runtime\dlls\manifest.json` from the DLLs on disk, and rebuilds `SyndicateLauncher.exe` with `-p:SyndicateDevBuild=true` (defines `DEV_BUILD`: shows the DEV LAUNCHER badge and the Studio button, and starts the backend with `TILTED_DEVKIT=1` for the Studio's map editor routes). State and build logs: `%LOCALAPPDATA%\PassionProject\dev\`.
- `MAKE DEV KIT.cmd` zips `Documents\Syndicate` to `Desktop\Syndicate-Dev-Kit-<date>.zip`.
- Player data (profiles, lockers, settings) lives in `%APPDATA%\SyndicateLauncher`, never in the repo or the Syndicate folder.

## Rules

- This is the public source release. Never commit secrets: Discord webhooks, bot tokens, relay URLs, signing keys, `.env` files or personal info. `SyndicateClassic/backend/src/Utils/syndicateLegacyXmpp.js` holds a self-signed loopback-only TLS key that old seasons need; it protects nothing.
- Never commit `.exe`, `.dll`, `.pdb`, build output (`bin/`, `obj/`, `x64/`, `dist/`), archives, `.env`, tokens, player data or Fortnite game files. `.gitignore` covers most of these.
- The launcher refuses to start the game when a DLL does not match `Runtime/dlls/manifest.json`. Any change that ships a new DLL must update that manifest.
- Syndicate targets 10.40 only. Code ported from `SyndicateClassic/` (Erbium, written against other builds such as 10.31) must be checked against Syndicate's 10.40 SDK and offsets, not copied as is.
- The bot rule applies to anything ported from `SyndicateClassic/`: arena bots must not teleport or get artificial protection.
- The Syndicate menu's ESP and aim features only ever affect bots, never real players.
- Season X loads the old `msvcp140.dll` from its own `Binaries\Win64`, so a DLL that loads into the game and links the shared C++ runtime (`SyndicateMenu.dll`) must not use `std::mutex` / `std::lock_guard` (they crash inside that older runtime); use a Windows `SRWLOCK` or `CRITICAL_SECTION`. `SyndicateStudio.dll` links the runtime statically and is not affected.
- No anti-virus evasion.
- Launcher colours are themable (Settings > Themes, `Services/ThemeService.cs`). Use `{DynamicResource ...}` for palette brushes (`AccentBrush`, `TextBrush`, ...) and the slots in `Resources/ThemeSlots.xaml` (`Accent_AA`, `Tint_AARRGGBB`, `TintColor_AARRGGBB`), never `StaticResource` or a hard-coded dark grey, or that part of the launcher will ignore the player's theme. Theme choices are saved in `settings.json` (`AppSettings.Theme`).
- `.cmd`/`.ps1` files use CRLF and must stay ASCII (Windows PowerShell 5.1 reads BOM-less files as ANSI).
- Commit messages and pull-request text belong to the project owner. Don't add AI/assistant attribution, "Generated with" lines, or `Co-Authored-By` trailers for Codebuff, Claude, or any other assistant; end the message at its own last line.
